## Chuẩn bị chung

Chuẩn hóa từng kênh màu về trung bình 0, độ lệch chuẩn 1, với thống kê **chỉ của train**:

```python
import time
tb = X[i_tr].float().div(255).mean((0, 2, 3)).view(1, 3, 1, 1)   # trung bình từng kênh đỏ, lục, lam trên train
dl = X[i_tr].float().div(255).std((0, 2, 3)).view(1, 3, 1, 1)    # độ lệch chuẩn từng kênh trên train
def chuan(xb):
    return (xb.float().div(255) - tb) / dl                       # uint8 thành số thực đã chuẩn hóa
print([round(v, 4) for v in tb.flatten().tolist()], [round(v, 4) for v in dl.flatten().tolist()])
```

```text title="Output"
[0.3453, 0.381, 0.4082] [0.2036, 0.1376, 0.1161]
```

Kênh đỏ tối nhất nhưng biến động nhiều nhất (độ lệch chuẩn gần gấp đôi kênh lam): ảnh vệ tinh phần lớn là thảm thực vật xanh, còn đỏ thì lúc có lúc không (mái nhà, đất trống).

Một hàm huấn luyện dùng cho cả chương, theo đúng công thức khởi đầu của Bảng 26.3: `AdamW`, và lịch <En>OneCycleLR</En>, tức warmup tăng dần learning rate trong 30% số bước đầu rồi giảm theo cosine về gần 0. Lịch này đếm theo **lô** nên gọi `lich.step()` sau mỗi lô (lỗi ở Chương 26).

```python
ce = nn.CrossEntropyLoss()
@torch.no_grad()
def du_doan(m, idx, pre=chuan, bs=500):
    m.eval()                                                     # batch norm dùng thống kê đã học, dropout tắt
    return torch.cat([m(pre(X[idx[i:i + bs]])) for i in range(0, len(idx), bs)])
def do_acc(m, idx, pre=chuan):
    return round((du_doan(m, idx, pre).argmax(1) == y[idx]).float().mean().item(), 4)
def huan_luyen(m, so_epoch, lr=1e-3, tang=None, pre=chuan, tham_so=None, bs=128):
    torch.manual_seed(1)
    opt = torch.optim.AdamW(tham_so if tham_so is not None else m.parameters(), lr=lr, weight_decay=1e-4,
                            fused=True)                          # bản gộp: chạy lại ra đúng từng chữ số
    lich = torch.optim.lr_scheduler.OneCycleLR(opt, max_lr=lr, total_steps=so_epoch * ((len(i_tr) + bs - 1) // bs))
    for ep in range(so_epoch):
        m.train()
        thu_tu, tong = i_tr[torch.randperm(len(i_tr))], 0.0      # xáo train mỗi epoch
        for i in range(0, len(thu_tu), bs):
            xb, yb = X[thu_tu[i:i + bs]], y[thu_tu[i:i + bs]]
            if tang is not None:
                xb = tang(xb)                                    # tăng cường dữ liệu, chỉ lúc huấn luyện
            loss = ce(m(pre(xb)), yb)
            opt.zero_grad()
            loss.backward()
            opt.step()
            lich.step()                                          # OneCycleLR đếm theo lô
            tong += loss.item() * len(xb)
        print(ep + 1, round(tong / len(i_tr), 4), do_acc(m, i_va, pre))
```

Mỗi dòng in ra: epoch, loss trung bình trên train, độ chính xác trên val.

Lần theo dấu thì nguyên nhân nằm ở bước cập nhật của `AdamW` mặc định: trên CPU nhiều luồng của máy viết bài, nó thỉnh thoảng cho kết quả lệch ở chữ số cuối giữa hai lần chạy. Lệch nhỏ đó lớn dần qua hàng nghìn bước, đủ để đổi vài ảnh từ đúng thành sai. Chạy một luồng thì hết lệch nhưng chậm hơn nhiều lần. Bài học: đặt seed là cần, nhưng muốn chắc chắn lặp lại được thì phải **chạy lại thật** và so sánh. Trên GPU còn nhiều nguồn lệch hơn; `torch.use_deterministic_algorithms(True)` là chỗ bắt đầu tìm hiểu.

## CNN

Mạng tích chập của Chương 27 và 28: bốn khối tích chập, batch norm, ReLU, max pooling. Mỗi khối giảm cạnh ảnh một nửa ($64 \to 32 \to 16 \to 8 \to 4$) và tăng số kênh gấp đôi, rồi lấy trung bình toàn cục và một lớp tuyến tính. Dropout 0,2 trước lớp cuối (Chương 26).

```python
def khoi(vao, ra):
    return nn.Sequential(nn.Conv2d(vao, ra, 3, padding=1), nn.BatchNorm2d(ra), nn.ReLU(), nn.MaxPool2d(2))
def tao_cnn():
    torch.manual_seed(0)
    return nn.Sequential(khoi(3, 32), khoi(32, 64), khoi(64, 128), khoi(128, 256),
                         nn.AdaptiveAvgPool2d(1), nn.Flatten(), nn.Dropout(0.2), nn.Linear(256, 10))
cnn = tao_cnn()
print(sum(p.numel() for p in cnn.parameters()))
huan_luyen(cnn, 15)
```

Mỗi epoch mất khoảng 57 giây trên CPU 16 nhân, gấp gần 10 lần MLP dù ít tham số hơn nhiều: phép tích chập ở lớp đầu chạy trên $64 \times 64 = 4096$ vị trí, mỗi vị trí 32 bộ lọc. Số tham số không nói lên lượng tính toán.

<Khung loai="doc-bieu-do">
Đọc cột val qua các epoch: không đi lên đều mà nhảy (ví dụ 92,1% ở epoch 6, rồi 86,8% ở epoch 7, 85,0% ở epoch 8). Đó là lúc learning rate đang ở đỉnh của OneCycle: bước lớn làm mô hình dao động. Nửa sau, learning rate giảm theo cosine, val ổn định dần và đạt cao nhất ở cuối. Vì thế, với lịch kiểu này, đừng dừng sớm ở giữa chừng chỉ vì val tụt một epoch.

## Tăng cường dữ liệu đúng với loại ảnh

<Term id="tang-cuong-du-lieu">Tăng cường dữ liệu</Term> (Chương 27, 28) phải giữ nguyên nhãn. Với ảnh chụp thường, lật ngang thì được, lật dọc thì không (con mèo lộn ngược không còn là ảnh bình thường). Ảnh vệ tinh nhìn **từ trên xuống**: lật ngang, lật dọc, xoay 90 độ, khu rừng vẫn là khu rừng. Ba phép lật ngẫu nhiên, mỗi phép với xác suất một nửa, tạo ra đủ $2^3 = 8$ biến thể (bốn góc xoay, mỗi góc có hoặc không lật):

```python
def lat_xoay(x):
    x = x.clone()
    m = torch.rand(len(x)) < 0.5
    x[m] = x[m].flip(3)                                          # lật ngang một nửa lô
    m = torch.rand(len(x)) < 0.5
    x[m] = x[m].flip(2)                                          # lật dọc một nửa lô
    m = torch.rand(len(x)) < 0.5
    x[m] = x[m].transpose(2, 3)                                  # đổi hàng thành cột: lật theo đường chéo
    return x
cnn_tang = tao_cnn()
huan_luyen(cnn_tang, 15, tang=lat_xoay)
```

Tăng cường đã làm đúng việc của một regularization (Chương 26): xóa khoảng cách train và val. Nhưng nó cũng làm bài **khó** hơn, mỗi ảnh mỗi epoch trông một kiểu, nên trong 15 epoch mạng chưa học đủ, và điểm val không lên. Đây là tình huống "regularization nhiều mà huấn luyện ít": cách chữa thông thường là huấn luyện lâu hơn, điều ta không thử ở đây vì mỗi 15 epoch đã mất 14 phút. Bài tập 32.1 thử một cách rẻ hơn: dùng các biến thể lúc **dự đoán**.
